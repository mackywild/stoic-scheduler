# ストイックスケジューラー MVP仕様書

## 1. プロダクトコンセプト

ユーザーが「何をするか」を選択する負荷を減らし、
現在の状況・空き時間・目標達成度・過去実績から、
アプリが今やるべき行動を1件だけ指示する。

## 2. MVP目的

1. 推薦 → 実行 → 結果記録のループを成立させる
2. 推薦精度改善に必要な行動履歴を集める
3. クラウド費用なしで実機検証できる
4. 後からFirebase/機械学習/LLMを追加できる責務分離にする

## 3. 対象OS

- iOS
- Android

Flutterによる単一コードベース。

## 4. 主要ユースケース

### UC-01 行動を登録する
ユーザーは行動名、優先度、1日の目標時間、最低/最大実施時間、
実行可能状況を登録する。

### UC-02 今の状況を指定する
通勤、食後、自宅、外出から選択する。

### UC-03 空き時間を指定する
5〜120分。

### UC-04 指令を受ける
推薦エンジンが実行可能な候補を採点し、最上位1件を返す。

### UC-05 完了する
実際の実施時間を入力して記録する。

### UC-06 スキップする
スキップ理由を記録する。

### UC-07 学習する
同じ「時間帯×状況×行動」の過去成功率を推薦スコアへ反映する。

## 5. 非機能要件

- MVPはオフライン利用可能
- 起動時に外部API不要
- 個人情報を外部送信しない
- 推薦ロジックは決定論的でテスト可能
- 推薦不能時は明示的に空状態を表示

## 7. 学習方式

MVPでは機械学習モデルを用いず、履歴ベースの成功率推定を利用する。

サンプル3件未満：
- 事前値 0.5

3件以上：
- Laplace smoothing
- successRate = (completed + 1) / (total + 2)

## 8. STOIC SCORE

現MVP：
- COMPLETE件数 / 全指令件数 × 100

将来：
- 難易度
- 優先度
- 連続日数
- 目標達成量
などを重み付けした独自スコアへ拡張。
